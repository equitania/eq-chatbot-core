# Phase 03.1: ElevenLabs Agents Realtime Provider - Context

**Gathered:** 2026-05-25
**Status:** Ready for planning
**Source:** PRD Express Path (docs/superpowers/specs/2026-05-25-elevenlabs-realtime-provider-design.md)

<domain>
## Phase Boundary

Deliver a new realtime provider, `ElevenLabsRealtimeClient`, as a **lean WebSocket transport adapter** for ElevenLabs Agents (speech-to-speech) that satisfies `RealtimeAdapterContract`, mirroring the existing OpenAI provider structure. It is registered **equal-rank** in the factory under the canonical name `"elevenlabs"`, redacts the `xi-api-key` from all logs, ships unit tests + a skip-safe integration test, and adds a README GDPR setup guide. ElevenLabs is positioned as the **preferred GDPR provider**; OpenAI, Gemini Live, and the Nova Sonic stub remain fully supported with no change to existing factory default behavior.

**Requirement promotion:** `PROV-FUT-03` (ElevenLabs Conversational AI) is promoted from future to a first-class recommended provider.

**Key nuance:** ElevenLabs Agents is **not an LLM** — it is a voice orchestrator (ASR + turn-taking + TTS) that calls an LLM under the hood. Full EU data residency requires an EU-hosted Custom LLM backend configured externally; the adapter does not enforce this (documented, not coded).
</domain>

<decisions>
## Implementation Decisions

### Role (Decision 1 — LOCKED)
- Full speech-to-speech realtime agent implementing `RealtimeAdapterContract` exactly like the other providers.

### GDPR enforcement (Decision 2 — LOCKED)
- Lean transport adapter taking `agent_id` + `api_key` only. EU Custom-LLM / Zero-Retention / EU region are configured **externally** in the ElevenLabs dashboard and **documented**, NOT enforced in code.

### Positioning (Decision 3 — LOCKED)
- Equal-rank registration in the factory under canonical name `"elevenlabs"`; positioned as the recommended GDPR choice in the README. No change to existing factory default behavior.

### Turn control (Decision 4 — LOCKED)
- `commit_client_turn()` and `create_response()` are **no-ops** — ElevenLabs performs server-side turn-taking (differs from OpenAI's manual commit).

### Config — `ElevenLabsRealtimeConfig` (LOCKED shape)
- `@dataclass(frozen=True, slots=True)` with fields: `api_key: str` (xi-api-key), `agent_id: str`, `base_url: str = "wss://api.elevenlabs.io"` (override with EU-residency endpoint), `voice: str | None = None`, `instructions: str | None = None` (→ `conversation_config_override.prompt`), `session_sample_rate: int = 16_000` (the override prepared in `contracts.py` for PROV-FUT-03).

### Client — `ElevenLabsRealtimeClient(BaseRealtimeWebsocketClient, RealtimeProvider)` (LOCKED)
- `__init__` fail-fast (D-03): `api_key` + `agent_id` must be non-empty **before any network I/O**.
- `_safe_url()`: the `xi-api-key` MUST NEVER appear in logs.
- Endpoint: `wss://{base_url}/v1/convai/conversation?agent_id={agent_id}`. Auth via `xi-api-key` header (private agent) or the signed-URL flow.

### Contract mapping (LOCKED)
- `connect()` → open WebSocket, await `conversation_initiation_metadata` → emit `SESSION_READY`
- `initialize_session()` → send `conversation_initiation_client_data` with `conversation_config_override` (prompt/voice/language)
- `append_client_audio()` → `user_audio_chunk` message (base64, **16 kHz**)
- `commit_client_turn()` → no-op
- `create_response()` → no-op
- `cancel_response()` → interruption handling
- `register_tools()` / `submit_tool_result()` → client tools
- `iter_normalized_events()` → event mapping below

### Event mapping (ElevenLabs → NormalizedRealtimeEventTypes — LOCKED)
- `conversation_initiation_metadata` → `SESSION_READY`
- `audio` → `RESPONSE_AUDIO_DELTA`
- `agent_response_complete` → `RESPONSE_DONE`
- `user_transcript` → `INPUT_AUDIO_COMMITTED`
- VAD / interruption → `INPUT_SPEECH_STARTED` / `INPUT_SPEECH_STOPPED`
- `client_tool_call` → `TOOL_CALL_COMPLETED`
- `ping` → keepalive (respond `pong`) — not emitted
- unknown → `UNHANDLED`

### Capabilities — `ELEVENLABS_REALTIME_CAPABILITIES` (LOCKED values)
- `streaming_audio_input=True`, `streaming_audio_output=True`, `server_vad=True`, `manual_turn_commit_required=False` (differs from OpenAI), `tool_calling=True`, `tool_result_submission_mode="conversation_item"` (VERIFY in research), `voice_selection=True`, `interruption_cancel=True`, `startup_validation=True`, `session_sample_rate=16_000`.

### Factory wiring — `realtime/factory.py` (LOCKED)
- `_build_elevenlabs_provider(**kwargs)` with a **deferred import**, registered under canonical name `"elevenlabs"`, equal-rank alongside `openai` / `gemini_live` / `nova_sonic`. Requires `agent_id` and `api_key`; raises a library-native error with a usage hint otherwise.

### Testing (LOCKED approach)
- `tests/unit/test_realtime_elevenlabs.py` — mocked WebSocket: event mapping, key redaction, fail-fast config validation, no-op turn methods.
- Integration test — **skipped when EU credentials absent** (mirrors the Gemini pattern in `tests/integration/test_realtime_gemini_live.py`): connect → `SESSION_READY` → clean disconnect. Must emit no secrets.

### GDPR setup guide — README / docs (LOCKED content)
- A dedicated section documenting the four conditions for full EU compliance: (1) Enterprise plan (EU residency is Enterprise-only), (2) Zero Retention Mode + API, (3) EU-hosted Custom LLM backend, (4) EU data-residency endpoint supplied as `base_url`. Caveat to document: **voice cloning is not Zero-Retention-eligible** (cloned voice models persist).

### Claude's Discretion
- Internal method naming, helper decomposition, and test fixture organization (follow the OpenAI/Gemini provider conventions).
- Docstring wording and code-comment density (match surrounding realtime providers).
</decisions>

<specifics>
## Specific Ideas

- WebSocket endpoint: `wss://{base_url}/v1/convai/conversation?agent_id={agent_id}` with `base_url` default `wss://api.elevenlabs.io`.
- Audio in: `user_audio_chunk` (base64, 16 kHz). Session sample rate fixed at 16_000.
- Session init message: `conversation_initiation_client_data` carrying `conversation_config_override` (prompt/voice/language).
- Keepalive: respond to `ping` with `pong`; do not surface as a normalized event.
</specifics>
