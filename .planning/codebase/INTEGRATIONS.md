# External Integrations

**Analysis Date:** 2026-05-11

## LLM Provider APIs

**OpenAI:**
- Purpose: GPT-4, GPT-4o, GPT-5, O1/O3/O4 series chat completions and streaming
- SDK: `openai>=2.0.0` (official Python SDK)
- Auth env var: `OPENAI_API_KEY` (passed by caller, not read from env by library)
- Implementation: `src/eq_chatbot_core/providers/openai_provider.py`
- Base URL: `https://api.openai.com` (default, overridable)

**Anthropic:**
- Purpose: Claude 3.5, Claude 4 Sonnet/Opus chat completions and streaming
- SDK: `anthropic>=0.90.0` (official Python SDK)
- Auth env var: `ANTHROPIC_API_KEY` (passed by caller)
- Implementation: `src/eq_chatbot_core/providers/anthropic_provider.py`
- Base URL: `https://api.anthropic.com` (default)
- Special: Supports prompt caching via `ChatMessage.cache_control` (added in v1.7.2)
- Retry: Exponential backoff for `OverloadedError` (529/503), up to 3 retries, max 30s delay

**LangDock:**
- Purpose: Unified EU/US API gateway for OpenAI, Anthropic, Google Gemini, Codestral, LangDock agents
- SDK: `httpx` (direct HTTP, no official SDK)
- Auth env var: `LANGDOCK_API_KEY` (passed by caller)
- Implementation: `src/eq_chatbot_core/providers/langdock_provider.py`
- Base URL: `https://api.langdock.com`
- Special: Region selection (EU/US for GDPR), reasoning effort for O1/O3/O4 models, agent knowledge folders
- Docs: `https://docs.langdock.com/api-endpoints/api-introduction`

**OpenRouter:**
- Purpose: Access to 400+ models from multiple providers via single API
- SDK: `openai` (OpenAI-compatible API)
- Auth env var: `OPENAI_API_KEY` / caller-provided key with `sk-or-` prefix
- Implementation: `src/eq_chatbot_core/providers/openrouter_provider.py`
- Base URL: `https://openrouter.ai/api/v1`

**Mammouth AI:**
- Purpose: Access to 30+ models via Mammouth gateway
- SDK: `openai` (OpenAI-compatible API)
- Auth env var: `MAMMOUTH_API_KEY` (passed by caller, `mm-` prefix)
- Implementation: `src/eq_chatbot_core/providers/mammouth_provider.py`

**Azure AI Foundry:**
- Purpose: GPT, Claude, Mistral and other models via Azure-hosted endpoints
- SDK: `azure-ai-inference>=1.0.0b9`, `azure-core>=1.30.0` (requires `[azure]` extra)
- Auth env var: `AZURE_API_KEY`, `AZURE_ENDPOINT` (passed by caller)
- Implementation: `src/eq_chatbot_core/providers/azure_provider.py`
- Base URL: caller-provided `https://your-resource.services.ai.azure.com/models`
- Client: `azure.ai.inference.ChatCompletionsClient`

**Google Vertex AI:**
- Purpose: Gemini 2.0/2.5 Flash and Pro models via Google Cloud
- SDK: `google-genai>=1.0.0` (requires `[vertex]` extra)
- Auth: Application Default Credentials (ADC) — `gcloud auth application-default login` or `GOOGLE_APPLICATION_CREDENTIALS` env var (service account JSON path)
- Implementation: `src/eq_chatbot_core/providers/vertex_provider.py`
- Project/Location: passed as kwargs to `get_provider("vertex", project="...", location="europe-west1")`
- No API key required (uses GCP IAM)

**Ollama:**

- SDK: `openai` (OpenAI-compatible)

## Data Storage

**Databases:**
- Qdrant (vector database)
  - Purpose: Vector storage and retrieval for RAG
  - Client: `qdrant-client>=1.12.0`
  - Implementation: `src/eq_chatbot_core/rag/retriever.py` (`HybridRetriever`)
  - Connection: passed as `qdrant_client` instance by caller (no built-in connection management)
  - Collections: caller-defined `collection_name`

**File Storage:**
- Local filesystem only (no cloud object storage)
- PDF files processed in-memory via `pymupdf` (`[pdf]` extra)

**Caching:**
- Anthropic prompt caching via `cache_control` on `ChatMessage` objects (API-level, not local cache)
- No local/Redis caching implemented

## Authentication & Identity

**Library auth model:**
- API keys passed explicitly by callers to `get_provider()`
- No environment variable auto-loading in library code
- Keys stored encrypted at rest using `FernetEncryption` (AES-128-CBC + HMAC-SHA256)
  - Implementation: `src/eq_chatbot_core/security/encryption.py`
  - Key management: caller's responsibility

**HTTP Gateway auth (`[server]` extra):**
- Bearer token middleware: `src/eq_chatbot_core/server/auth.py` (`BearerTokenMiddleware`)
- Token generated by parent process, passed via `--auth-token-fd` CLI flag
- No OAuth, no session management — single shared token

## Security Components

**Prompt Injection Detection:**
- Implementation: `src/eq_chatbot_core/security/injection.py`
- Used to detect adversarial inputs before sending to LLM

**Rate Limiting:**
- Implementation: `src/eq_chatbot_core/security/rate_limit.py`
- Token bucket algorithm (client-side)

**File Validation:**
- Implementation: `src/eq_chatbot_core/security/file_validator.py`
- MIME-type verification via `puremagic` (requires `[security]` extra)

**MCP Client SSRF Protection:**
- Implementation: `src/eq_chatbot_core/mcp/client.py`
- `_validate_url()` blocks private/reserved IP ranges and non-HTTP(S) schemes
- `ALLOWED_STDIO_COMMANDS` allowlist for subprocess execution
- Shell metacharacter blocking for stdio args

## MCP Protocol

**MCP Client:**
- Purpose: Tool execution via Model Context Protocol (spec 2024-11-05)
- Transports: SSE (HTTP) and stdio (subprocess)
- Implementation: `src/eq_chatbot_core/mcp/client.py`
- Allowed stdio commands: `python`, `python3.x`, `node`, `npx`, `uvx`, `uv`
- No external SDK — custom JSON-RPC implementation over httpx

## HTTP Gateway (Sidecar Mode)

**REST API server (`[server]` extra):**
- Purpose: Cross-language integration (e.g., Avalonia desktop app spawning as sidecar)
- Framework: FastAPI + Uvicorn + sse-starlette
- Implementation: `src/eq_chatbot_core/server/app.py`
- Endpoints:
  - `GET /health` — liveness probe (no auth), returns version + uptime
  - `GET /providers` — static provider catalog
  - `POST /models` — per-provider model list (API key in body, not URL)
  - `POST /chat` — single-shot chat completion
  - `POST /chat/stream` — SSE streaming of token deltas
- Auth: all non-health endpoints guarded by `BearerTokenMiddleware`
- CLI: `eq-chatbot serve --auth-token-fd <fd>`

## CI/CD & Deployment

**Hosting:**
- PyPI (`eq-chatbot-core`) — published manually by maintainer

**CI Pipeline:**
- GitHub Actions: `.github/workflows/ci.yml`
- Triggers: push/PR to `main`
- Jobs:
  - `lint`: ruff check + format check + mypy (advisory, `continue-on-error: true`) on Python 3.12
  - `test`: pytest unit tests on Python 3.10/3.11/3.12/3.13 matrix (live/local tests skipped via `SKIP_LIVE_TESTS=true`)
  - Coverage XML uploaded as artifact from Python 3.12 run
- Build/publish: **not in CI** — run locally by maintainer

**No webhooks, no incoming callbacks** — pure library, no server-side endpoints in production.

- `LANGDOCK_API_KEY`
- `MAMMOUTH_API_KEY`
